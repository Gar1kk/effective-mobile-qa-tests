# Тестовое задание Effective Mobile — QA

Проект выполнен для КТ2 по дисциплине «Основы IT-технологий».

**Основная роль:** тестировщик (QA)

**Компания:** Effective Mobile

**Исходное задание:** https://github.com/Hexlet/ru-test-assignments/blob/main/qa/effective-mobile/README.md

## 1. Что сделано

В проекте реализованы два автоматических теста на Python.

**UI-тест (`tests/test_purchase.py`)**

Проверяет покупку товара на сайте https://www.saucedemo.com/:

1. Авторизация тестового пользователя.
2. Добавление рюкзака Sauce Labs Backpack в корзину.
3. Проверка товара в корзине.
4. Заполнение данных покупателя.
5. Оформление заказа.
6. Проверка сообщения об успешной покупке.

Используются Selenium и pytest.

**API-тест (`test_api.py`)**

Проверяет работу с GitHub API:

1. Создаёт новый публичный тестовый репозиторий.
2. Проверяет его наличие в списке репозиториев.
3. Удаляет созданный репозиторий.
4. Проверяет, что после удаления API возвращает ответ 404.

Используются requests, python-dotenv и pytest.

## 2. Что не делаю

Не выполняю дополнительные сценарии покупок, нагрузочное тестирование и проверки других пользователей. Эти задачи не входят в основные требования выбранного тестового задания.

## 3. Установка

Для запуска необходимы:

- Python 3.12
- Google Chrome для UI-теста
- Доступ к интернету

Скачайте проект с GitHub:

https://github.com/Gar1kk/effective-mobile-qa-tests

Откройте папку проекта в PyCharm или терминале.

Установите библиотеки командой:

`python -m pip install -r requirements.txt`

## 4. Настройка GitHub API

Для API-теста необходим GitHub Personal Access Token (classic) с разрешениями `public_repo` и `delete_repo`.

Создайте в корне проекта файл `.env` по образцу `.env.example`.

В Windows PowerShell можно использовать команду:

`Copy-Item .env.example .env`

Заполните файл `.env`:

`GITHUB_USERNAME=ваш_логин`

`GITHUB_TOKEN=ваш_токен`

`GITHUB_REPO_NAME=qa-api-test-temp`

Настоящий токен нельзя публиковать. Файл `.env` добавлен в `.gitignore`.

**Внимание:** API-тест создаёт и удаляет настоящий временный репозиторий в аккаунте GitHub. Используйте отдельный краткосрочный токен. После тестирования рекомендуется отозвать его. При ошибке временный репозиторий может потребовать ручного удаления.

## 5. Запуск тестов

**Запуск UI-теста:**

`python -m pytest tests/test_purchase.py -v -s`

**Запуск API-теста:**

`python -m pytest test_api.py -v -s`

**Запуск всех тестов одновременно:**

`python -m pytest -v -s`

## 6. Проверка результата

Для UI-теста успешным результатом считается появление сообщения `Thank you for your order!`.

Для API-теста проверяются ответы GitHub API при создании, поиске и удалении репозитория. После удаления дополнительно проверяется ответ `404`.

При успешном выполнении pytest показывает `PASSED`.

При локальной проверке на Windows с Python 3.12 оба теста успешно прошли:

`2 passed in 14.52s`

Отдельная проверка улучшенного API-теста также завершилась успешно:

`1 passed in 10.49s`

## 7. Структура проекта

- `tests/test_purchase.py` — UI-тест оформления покупки.
- `test_api.py` — тест GitHub API.
- `requirements.txt` — необходимые библиотеки.
- `.env.example` — пример настроек.
- `.gitignore` — исключение временных и секретных файлов.
- `README.md` — описание проекта и инструкция по запуску.
